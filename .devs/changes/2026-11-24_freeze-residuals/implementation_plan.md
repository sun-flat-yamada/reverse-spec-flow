# 実装計画: C6 凍結記録の検査（T-FREEZE）に残る fail-open を塞ぐ

改善候補レビュー（2026-11）の C6。`dev/developing-the-framework.md` の「未着手」のうち、検査が素通りする穴として残っているものを塞ぐ。

## 対象の選定（実測）
- 「効果測定 E3 の fail-open」FO-1〜4 は塞ぎ済み・撤回済み。「プレースホルダ／分母の判定の残件」は解消済みか、
  **実データで発火 0 件のため据え置き**と決めてある（3・5・9・10）。実データが無いまま着手しない（文書の方針どおり）。
- 残るのは「凍結記録の `T-FREEZE` に残る残件」6 件。うち検査の穴は次の 2 件で、これを塞ぐ:
  - **残件 1**: 再凍結の履歴の追記を強制していない。主表のハッシュだけ書き換えて履歴を書かなくても緑になる（FB-6 の型）。
  - **残件 3**: `freeze-state` の語の集合を、記録側の散文（「取りうる値は…」）への grep で見ている。言い換えると黙って落ちる。
- 残件 2（同一内容 2 ファイル）は実害 0 件、4（done の裏付け）は記録の書式の変更を伴い、5 は文書の形、6 は既知の見逃しとして判断済み。今回は扱わない。

## 方針
- 残件 1: 凍結記録ごとに、git の履歴で「ハッシュ表（主表＋Playbook 表）が変わった版」を列挙し、**その版で履歴の日付行が増えていること**を要求する。
  対象は記録に触れた各コミット（親と比べる）と、未コミットの変更（HEAD と比べる）。比較の判定は 1 つの関数にし、注入検査（ハッシュだけ変えた写し → 赤、履歴行も足した写し → 緑）を対で置く。
  履歴が浅い（親が無い）コミットは比べられないので数を出す（黙って通さない）。
- 残件 3: 記録に機械可読のマーカー `<!-- freeze-state-values: pending done -->` を置き、検査はそれを読む。
  マーカーの値の集合が、検査が分岐で扱う値（pending / done）と一致しないなら赤にする（第三の値を足すなら実装と対で直す）。
- `dev/developing-the-framework.md` の残件表の 1・3 を解消済みにする。

## 検証
- `./selftest.sh` が base より失敗を増やさない。追加した注入検査が両方向で発火する。
- 別コンテキストの反証レビュー。
